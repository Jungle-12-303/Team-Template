# 회의록 작성 스킬

## 개요

회의록은 **자주, 간결하게** 정리하는 것이 목표입니다.
양식은 WIKI 프로젝트의 `docs/meeting-minutes/TEMPLATE.md`를 따릅니다.

---

## 양식

```markdown
# 회의록 — YYYY-MM-DD (Week N)

**참석자:** @이름1, @이름2, ...

| 안건 | 결정 상태 | 결정 내용 |
|------|-----------|-----------|
| 안건 1 | 결정 / 보류 / 논의 중 | 결정된 내용 요약 |

## 할 일 (있다면)

- [ ] 할 일 — 담당: @이름, 기한: MM-DD
```

---

## 실행 절차

### Step 1: 정보 수집

사용자가 제공한 내용에서 추출:

| 항목 | 필수 여부 | 없으면 |
|------|-----------|--------|
| 날짜 | 필수 | 오늘 날짜로 제안 |
| 참석자 | 필수 | 질문 |
| 안건 (최소 1개) | 필수 | 질문 |
| 결정 상태 | 선택 | "논의 중"으로 표기 |
| 결정 내용 | 선택 | 빈칸 |
| 할 일/담당자/기한 | 선택 | 섹션 생략 |

### Step 2: 부족한 정보 질문

필수 항목이 빠졌으면 한 번에 질문:

```
회의록 작성을 위해 확인할게요:
1. 회의 날짜가 오늘(YYYY-MM-DD)이 맞나요?
2. 참석자가 누구였나요?
```

### Step 3: 작성

- 파일명: `YYYY-MM-DD.md`
- 경로: WIKI 프로젝트의 `docs/meeting-minutes/weekN/`
- 안건마다 결정 상태를 **결정 / 보류 / 논의 중** 으로 표기
- 할 일이 없으면 "할 일" 섹션 자체를 생략
- 불필요한 해석 없이 사실만 기록

### Step 4: 검토 요청

```
회의록을 작성했습니다. 빠진 안건이나 수정할 내용이 있으면 말씀해주세요.
```

---

## 주의사항

- 복잡하게 쓰지 않기. 테이블 한 장이면 충분합니다.
- 결정이 안 난 안건은 "보류"로 남기고 다음 회의로 넘기기.
- 매번 완벽하게 쓰려고 하지 않기. **자주 쓰는 게 더 중요합니다.**
